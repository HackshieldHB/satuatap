# Energy node firmware — `esp32-energy-001`

Real firmware for the first Fase D board. One ESP32 reads **two PZEM-004T v3.0**
meters and publishes telemetry for two logical devices, replacing the two
`energy-*` devices that `apps/iot-simulator` fakes.

| PZEM | Logical device | Meaning       |
| ---- | -------------- | ------------- |
| #1   | `energy-main`  | main panel    |
| #2   | `energy-ac`    | AC circuit    |

Sketch: [`esp32-energy-001/esp32-energy-001.ino`](esp32-energy-001/esp32-energy-001.ino).

## MQTT contract (identical to the simulator)

```
home/home-1/device/energy-main/telemetry     {ts, metrics:{voltage,current,power,energy_kwh,frequency,power_factor,rssi}}
home/home-1/device/energy-ac/telemetry        (same shape)
home/home-1/node/esp32-energy-001/availability  {status,...}   retained + LWT
```

`energy_kwh` is the PZEM's cumulative kWh counter. The cloud ingest turns it into
per-reading deltas (`energy_kwh_delta`) and tolerates late / out-of-order readings
(see `apps/api/src/ingest.ts`), so a board that reconnects after an outage backfills
correctly.

## Authentication — per **node**, not per device

A physical board hosts multiple devices, so it authenticates **once** as the node.
Username = the nodeId (`esp32-energy-001`); its ACL (generated by
`scripts/mqtt-acl.ts`) permits writing telemetry/state/ack/event for exactly the
devices it hosts plus its availability topic. Do **not** use a device credential or
the `simulator` account.

Password: `.secrets/mqtt-dev-passwords.json` in the repo root, key
`"esp32-energy-001"`. It is regenerated on every `npm run db:seed` — recopy after a
reseed. (Node credentials are also stored hashed in the `NodeCredential` table.)

## Wiring

```
PZEM #1 (energy-main)  TX -> GPIO16 (RX1)   RX -> GPIO17 (TX1)
PZEM #2 (energy-ac)    TX -> GPIO27 (RX2)   RX -> GPIO26 (TX2)
All GND common. AC side (L/N + CT coil) per the PZEM manual.
```

> **WROVER boards:** GPIO16/17 are used by PSRAM — move UART1 to other free pins
> (e.g. 25/33) and update `PZEM_PINS` in the sketch. WROOM-32 is fine as-is.

## Flash

1. Arduino IDE → Library Manager: install **PubSubClient** (Nick O'Leary) and
   **PZEM004Tv30** (Jakub Mandula). Board: **ESP32 Dev Module**.
2. Copy `arduino_secrets.h.example` → `arduino_secrets.h` (gitignored) and fill it:
   `SECRET_WIFI_*`, `SECRET_MQTT_HOST` (the laptop/Pi LAN IP — `setup.bat` prints it),
   and `SECRET_MQTT_PASSWORD` (the node password from `.secrets`, key `esp32-energy-001`).
3. Ensure the stack is up (`setup.bat`) and the **simulator is OFF** for these two
   devices (else the fake `energy-main`/`energy-ac` counters collide with the board).
4. Upload, open Serial Monitor at 115200. Expect `[mqtt] ... OK`, then per-cycle
   `energy-main OK  energy_kwh=...`. Verify on the dashboard `/energy` page and that
   `/devices` shows both devices Online.

Chain proven end-to-end by `firmware/bench` before real sensors were attached.
